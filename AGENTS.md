# Instructions for coding agents

Before making changes, read [the technical documentation index](doc/README.md) and any linked topic relevant to the task. Follow the safety boundaries, data contracts, and verification commands documented there.

Treat `doc/` as internal project documentation. Keep it outside `public/` and the production build, preserve the Vite request block for that directory, and never deploy the repository root as a static site. Do not put secrets, personal data, real client information, or production financial advice in source, tests, or docs.

For changes to user-visible behavior, update the relevant technical docs and test the precise behavior. Ask for review before adding a backend, AI provider, real market data, user authentication, regulatory rules, or any operation capable of changing or executing a portfolio.
